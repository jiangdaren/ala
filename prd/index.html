1、项目背景

1.1 业务现状

白领与互联网从业者的工作信息高度分散：日常沟通分布在飞书、钉钉、企业微信、微信四个 IM，正式事项在邮件与日历，临时想法在便签和聊天窗口。现有工具各自为政——IM 自带待办只覆盖本平台，独立待办 App（滴答清单、Things）需要手动切换应用录入，笔记类工具（Notion、flomo）不主动提醒。

结果是：信息在眼前流过，但没有一个低成本的动作能把它留下来。

1.2 面临问题

按「影响范围 × 严重程度 × 紧迫度」排序：

  1. 记录成本过高导致漏事：从看到一条"周五前给我方案"到把它记进待办，需要切窗口、开应用、新建、填标题、选时间——约 15 秒和 5 次操作。代价大于收益时，人的选择是不记，然后遗忘。
  2. 信息分散无统一入口：四个 IM + 邮件 + 日历，没有任何一个地方能看到"我今天到底欠了哪些事"。
  3. 工作成果不可回溯：每天都很忙，任务一件接一件，但过一段时间根本想不起来最近做了些什么，忙忘了。到了周报、月报、述职、绩效考核时，只能翻聊天记录回忆，耗时且失真。 注意后果的分量：这不只是"周报难写"这种日常麻烦，它直接影响述职与绩效考核——也就是影响个人的职业评价。这决定了成果统计的两条设计底线：周期必须覆盖到季度与年度；导出物必须每条可回溯到原始出处，否则拿到述职场合上不可信。
  4. 个人知识资产沉睡：历年方案、会议纪要、行业资料躺在硬盘里，需要时想不起在哪，更无法在与 AI 对话时被调用。

1.3 解决思路

把赌注全押在摩擦系数上，而不是功能数量上。

核心动作只有一个：选中信息 → 按一个快捷键 → 结束。分类、时间、优先级、责任人全部由 LLM 事后补，补错了在列表里改。用户只负责"触发"，不负责"整理"。

在此基础上，把积累的数据反哺成成果看板与个人知识库。

⏸ 2026-09-20 改写：本段原写「逐步接入合法的自动数据源（飞书 / 钉钉群消息、邮件、日历）， 把手动捕获升级为自动流入」。IM 三家已无限期暂缓（SRS §8 矩阵注）， 「升级为自动流入」这一步在 V1/V2 不会发生。 邮件与日历仍在 V2，但它们承接的是「正式事项」，不是 IM 里的口头承诺—— 口头承诺这条最主要的来源，产品只打算靠手动接住。 于是阿拉当前的形态是低摩擦手记器，不是自动归集器； 这不是措辞问题，它决定了第二段验证该验什么（见 SRS §9 第 3 条）。

核心场景描述

场景 1：会议中被 @ 了一件事

  • 人物：产品经理，同时开着飞书、微信、邮件
  • 时间：工作日下午，正在写方案
  • 地点：电脑前，飞书群消息弹出
  • 起因：同事在群里说"这个方案周五前发我看下"
  • 经过：现在的做法是——看到 → 心想"等下记一下" → 继续写方案 → 忘了。或者切到待办 App，新建，填标题，选时间，回来时思路已断
  • 结果：要么漏事，要么被打断。两个结果都很贵

场景 1b：我派出去的事，没人替我盯着（2026-09-16 新增）

  • 人物：同一位产品经理
  • 时间：周三上午，群里讨论到一半
  • 起因：他跟研发说"这版报表的口径改一下，周一之前给我，我过一遍再发客户"
  • 经过：这句话说完，事情在他心里就已经卸下了——"我派出去了"。 但没有任何系统记下这件事：不是需求、不进 Jira、只是聊天里的一句话。 周一他没想起来问，研发那边也忘了。
  • 结果：周三客户来要，两边才发现谁都没做。
  • 本质：这和场景 1 是方向相反的两件事。 场景 1 至少还有对方惦记着会来催你；这里没有人会来催你—— 你不是忘了做事，是忘了自己在等什么，而后果仍然由你承担。 恰恰因为"派出去了"这个心理卸载，它比场景 1 更不容易被记下来。

两个场景共用同一个动作：选中那句话，按一下。 区别只在系统怎么理解它——owner 是空还是一个人名（本体论 v2.11「三种承诺关系」）。 2026-09-16 真模型实测：这个方向模型判得准，「我让张三下周一之前把报表改好， 改完我这边过一遍」会被自己拆成「张三改报表」+「我过一遍」两条。

场景 2：述职前，想不起自己做过什么

  • 人物：同一位产品经理
  • 时间：季度末，或任何要交周报月报的时点
  • 起因：要写周报 / 月报 / 述职材料 / 绩效自评
  • 经过：每天都很忙，任务一件接一件，但过一段时间根本想不起来做过什么。只能翻飞书聊天记录、翻邮件、翻本地文件，一点点回忆
  • 结果：耗时 40 分钟以上，且大概率漏掉一半工作。在述职与绩效场合，漏掉的那一半等于没做过
  • 本质：这不是"写材料麻烦"，是遗忘导致的价值流失——做过的事没被记住，就等于没发生

场景 3：想找一份两年前的方案

  • 人物：同上
  • 起因：客户问到一个历史项目的做法
  • 经过：在硬盘里搜关键词，记不清文件名，翻了 20 分钟
  • 结果：找到了，但会议已经过去了

3、商业分析

💡 方法论提示：商业化产品适用「目标市场 → 客户画像 → 痛点 → 卖点 → 竞品」链路，并补充 SaaS 关键指标预估。

3.1 目标市场与客户分析

市场特征：个人效率工具赛道成熟且拥挤。「跨 IM 的工作信息归集」确实是一个尚未被现有产品正面解决的细分点——门槛不在技术，在数据授权。

⏸ 2026-09-20：但这不再是我们的差异点。 IM 接入已无限期暂缓， 一个我们也不解决的问题，不能拿来当卖点。 当前真实的差异点只剩一条，而且它必须自己立得住： 从看到信息到记录完成的秒数（实测 P95 33ms，NFR-PERF-01）。 数据授权这道门槛现在是别人的护城河，不是我们的——若哪天我们恢复接入，才谈得上翻越它。

客户痛点排序：① 漏事 → ② 记录费劲 → ③ 成果说不清 → ④ 知识找不到

①「漏事」要拆成两种（2026-09-16）： 我欠人家的漏了 → 被催，丢面子； 人家欠我的漏了 → 没人催，事情静静地黄掉，责任还在我。 后者更隐蔽，且目前没有任何工具在管它。

价值的可测定义（对内，用来证伪，不对外说）：

把「记录一条跟人说定的事」的成本，从 20–40 秒 + 一次上下文切换， 降到 约 2 秒 + 零切换；让没有截止时间的那 92% 也能被提醒到； 并让「我在等的事」和「我要做的事」一样有人盯着。

三个数字任何一个不达标，卖点第 1 条就不成立。

⚠️ 口径：33ms 是「按下到出现反馈」的系统耗时，不是用户总耗时。 用户总耗时约 2 秒（选中 1–2 秒 + 按键）。差距是 10–20 倍，不是 600 倍—— 不拿漂亮但不诚实的数字说话。

R32 约束 问答以三类为依据：待办及其来源原文 / 成果统计 / 知识库文档；可结合 AI 通用能力给出信息、建议与方案，按人机边界分两块呈现（2026-09-28 改，原为「三类之外不答」）
R33 计算 问答给出的统计数字必须复用 R23~R27 的同一套计算，不得自行再算一遍——两处各算一遍迟早对不上，而用户会同时看见这两个数字
R34 约束 单轮问答请求只允许携带本轮检索命中的切块原文，不得携带历史轮次的原文片段（FR-KB-04）
R35 约束 无引用即不是你的数据：未附来源的内容一律归入「AI 的建议」，不得表述为来自用户的资料；资料里没有相关内容时先说「你记过的东西里没有这个」（2026-09-28 改）
R36 约束 对话历史留在本地、不参与向量索引，随「清除全部数据」一并清除

10.3 异常情况处理方案

异常类型 异常场景 处理方案
网络异常 捕获时无网络 Signal 正常落本地，进待解析队列；联网后自动补做 LLM 解析，完成后静默通知
网络异常 适配器长连接中断 指数退避自动重连（5s→30s→5min），界面显示异常徽标，其余功能不受影响
外部服务异常 LLM 返回错误或超时 重试 2 次；仍失败则进待解析队列，连续 3 次失败时提示用户并提供手动建待办入口
外部服务异常 LLM 返回不符合 Schema 的内容 直接判为解析失败，进待确认队列，绝不把自由文本当 Task 入库
数据异常 数据库损坏 启动时校验，损坏则自动切换到最近备份并提示；每日自动本地备份，保留 7 份
数据异常 附件文件丢失 待办仍可用，来源展开时提示"原始附件已丢失"，不影响其他功能
并发冲突 待办与飞书待办双向同步冲突 ⏸ 暂缓（2026-09-20），当前无任何外部双写 恢复接入时复活：以最后修改时间为准，冲突时保留两份并提示用户选择
误操作 误删待办 软删除，30 天内可在回收站恢复
误操作 误触发捕获 捕获反馈气泡中提供 5 秒内「撤销」
权限异常 系统权限（辅助功能/通知/截图）被拒绝 明确提示缺少哪个权限、影响哪个功能、如何开启，其余功能照常
权限异常 IM 敏感权限被管理员拒绝 自动降级为仅接收 @本人 消息，界面明确说明当前覆盖范围
业务异常 待办长期逾期未处理 逾期置顶高亮；连续 7 天未处理时小狗主动提示"要不要放弃这条"
性能异常 待办数据量过大导致列表卡顿 分页加载 + 索引优化；超过 1 万条时提示归档
